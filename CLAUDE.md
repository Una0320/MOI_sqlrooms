# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A high-performance city-mobility trajectory visualizer built on **SQLRooms + Deck.gl + DuckDB-WASM**. It renders 20,000+ Agent-Based Modeling (ABM) trajectories from Parquet entirely in the browser, using zero-copy Arrow → GPU rendering and in-browser SQL aggregation. Originally derived from the official SQLRooms `deckgl-example`; now extended into a **civil-protection scenario viewer** with two top-level scenario types (shelter-in-place / mass-evacuation), each with its own trajectory data, OD arcs, and scenario-specific overlay layers (transit stations/waiting crowds vs. shelters/capacity).

## Commands

```bash
yarn install      # install deps (yarn is the lockfile of record; package-lock.json also present)
yarn dev          # Vite dev server
yarn build        # tsc -b && vite build
yarn lint         # eslint .
yarn preview      # preview production build
```

There is no test suite. `.env` needs `VITE_DUCKDB_CONNECTION_STRING` (base URL of a local HTTP server that supports **Range Requests**, default `http://localhost:7780`) — every actual filename is resolved from `src/constants/data.ts`'s manifest via `resolveFiles({scenario, control, sampleSize})` (see below), not from individual `.env` vars anymore. `VITE_MAPTILER_API_KEY` is optional: set it to make the default ("current") basemap MapTiler's `dataviz-dark` (rebuilt weekly) instead of CARTO's `dark-matter-gl-style` (OSM data rebuilt as infrequently as once a year per CARTO's own docs) — get a free key at cloud.maptiler.com/account/keys. Missing the key just falls back to CARTO with a console warning, it doesn't break local dev. All basemap config lives in `src/constants/basemap.ts` (see "Basemap" below).

### Local test data (`sim_data/`)

Local development points at whichever single delivery folder currently exists under `sim_data/` — folder naming varies per delivery (not always a date; currently `sim_data/20261023/`) — a delivered test batch (git-ignored, ask for a fresh copy if missing) with its own `README.md` describing 7 subfolders (`02_points`, `03_stop_counts`, `04_shelter_capacity`, `05_moi_sim/<run>/`, `06_road_service`, `07_road_control`, `08_heatmap`; `01_trajectory` is retired) across 6 runs `s{1,2,3}_{none,ctrl}` (s1 大規模撤離 / s2 混合避難 / s3 優先疏散; `none` = 無路網管制, `ctrl` = 有路網管制) × 4 trajectory/OD sample sizes (`a10000/40000/50000/70000` agents; smaller ⊂ larger, same households in all six runs). All of it is wired up through the manifest in `src/constants/data.ts`: trips + OD arc (`05_moi_sim`), Stop Counts (`03_stop_counts` + the `02_points` CSVs as coordinate join), Shelter Capacity (`04_shelter_capacity`, s2/s3 only), Road Service (`06_road_service`, hourly `level` 1–6), Road Control (`07_road_control`, one shared file for the three `ctrl` runs) and Heatmap (`08_heatmap`, per-run 5-min × link × mode counts + shared `heatmap_links.parquet`). The old `pt*` / `evac_ratio*` data and the `ratio` axis are gone.

Since `sim_data/` isn't served anywhere in production, local dev needs a standalone static file server with Range + CORS support pointed at it, e.g.:

```bash
npx http-server sim_data/<delivery-folder> -p 7780 --cors   # e.g. sim_data/20261023 — check what's actually on disk
```

`VITE_DUCKDB_CONNECTION_STRING` just needs to match that server's base URL.

## Architecture

### Scenario switching (shelter-in-place vs. mass-evacuation)

- `useMapStore` holds three independent selectors — `scenarioType: 'mass_evacuation' | 'mixed_shelter' | 'priority_evac'` (default `'mass_evacuation'`), `sampleSize: 10000 | 40000 | 50000 | 70000` (default 10000 = `DEFAULT_SAMPLE_SIZE`; the agent count of the trips/OD files, picked with the `抽樣 1萬 | 4萬 | 5萬 | 7萬` segmented control in the Timeline header, see "Timebar") and `networkControl: boolean` (default `false`). `setScenarioType` / `setSampleSize` / `setNetworkControl` all reset `time`/`timeRange`/`isPlaying` to their defaults (time axes differ per run — leaving the playhead would silently show nothing). `networkControl` is deliberately **not** touched by `setScenarioType`, so the switch survives scenario changes.
- `<ScenarioSwitcher />` (top-center) is the scenario UI: three tabs 大規模撤離 / 混合避難 / 優先疏散 (`SCENARIO_ORDER` in `data.ts`; 就近避難 and its `evac_ratio*` manifest entries were deleted with the 20261023 delivery). A tab is disabled (title 「資料尚未提供」) when no sample size has data under the current control setting (never true for the current batch). The sample-size selector is **not** here — it lives in the Timeline header (`timebar/SampleSizeSelector.tsx`). `<NetworkControlToggle />` (top of the right-hand stack) is the Network Control switch; it enables the `ctrl` runs and the Road Control layer, and stays clickable once on so it can be turned off.
- `src/constants/data.ts` holds the file manifest: `resolveFiles({scenario, control, sampleSize}): FileSet` **builds** the paths from the run code (`s1/s2/s3` × `none/ctrl`, via `SCENARIO_CODE`) — there is no lookup table any more; an unknown sample size returns an all-`null` set. `FileSet` fields are each independently nullable — `dataUrl`, `odDataUrl`, `stopCountsUrl`, `shelterCapacityUrl` (`null` for mass_evacuation: nobody goes to shelters), `roadServiceUrl`, `roadControlUrl` (`null` unless `network_control`), `heatmapUrl`, `heatmapLinksUrl`. Helpers: `isAvailable` (has `dataUrl`), `isScenarioAvailable`. Consumers never read the manifest directly — they use `hooks/useResolvedFiles.ts`, which resolves from the store (`MainView.tsx`, `timebar/TimeLine.tsx`, every layer hook, `useEvacuationRate.ts`) and rebuild their query from it every render; `useSql` refetches when the query string changes. A `null` url makes the owning hook run a guaranteed-zero-row query instead of erroring; `MainView` shows 「此組合無資料」 instead of the map when `dataUrl` is `null`. The big lazy tables (Road Service, Road Control, Heatmap) also run the zero-row query while their layer is switched off, so they are only downloaded the first time the layer is turned on.
- Layer availability is driven purely by the manifest: each `LAYER_CONFIG` entry has `requires: keyof FileSet` (e.g. `SHELTER_CAPACITY` → `'shelterCapacityUrl'`, `STOP_COUNTS` → `'stopCountsUrl'`), and `LayerPanel.tsx` shows **every** panel layer, disabling (not hiding) those whose url is `null` with 「此組合無資料」 (the hint sits on its own line under the title). The hooks also gate on the url being non-null.

### Single DuckDB engine (SQLRooms connector)
All in-browser SQL goes through **one** DuckDB-WASM instance — the SQLRooms connector created in `src/store.ts` via `createWasmDuckDbConnector()`. It drives the app's data loads below; the RoomShell chrome that used to expose it directly (sidebar with a SQL Editor / Data panel / file-dropzone / command palette toggle) was removed from `src/room.tsx` — it's end-user-facing product now, not a debug dashboard. `DataPanel.tsx` and the `data` panel registration in `src/store.ts` are still there (unreachable, harmless) so the sidebar can be added back trivially if that tooling is needed again later.
- **Trajectory load** — `MainView.tsx` uses the SQLRooms `useSql({query})` hook (`SELECT paths, timestamps, modes FROM read_parquet('${dataUrl from useResolvedFiles()}')`); the resulting `data.arrowTable` is passed as a **prop** to `<MapView arrowTable=... />`, which in turn feeds it to the trips layer and `usePointsLayer` (both share the one query result — zero extra DuckDB round-trips; Heatmap has its own query, see below).
- **Histogram** — `timebar/TimeLine.tsx` uses `useSql` for the time-bin aggregation query, also against the current scenario's `dataUrl`.
- **OD-arc load** — `hooks/useODArcLayer.ts` runs its own `useSql({query: 'SELECT * FROM read_parquet(odDataUrl)'})` against the scenario's OD parquet, since OD data has a different schema/granularity than the trip trajectories. Still the same connector, just a second query.
- **Stop Counts load** — `hooks/useStopCountsLayer.ts` runs one `useSql` query that joins `03_stop_counts` (per-stop, per-time-bucket waiting counts) against `bus_stops.csv`/`metro_stations.csv` (for coordinates) via `LEFT JOIN ... ON mode = 8/16`.
- **Shelter Capacity load** — `hooks/useShelterCapacityLayer.ts` runs one `useSql` query against `04_shelter_capacity` directly (X/Y/name/capacity are already baked into that table, no join needed).

`useSql` returns `{ data: { arrowTable, rows(), toArray() }, isLoading, error }` and handles connector-init timing. Remote `read_parquet('http://...')` works natively in duckdb-wasm via Range requests. (Historically there were three separate DuckDB instances + a `window.globalArrowTable` hack; that was consolidated — do not reintroduce it.)

### State management
- **SQLRooms RoomShell store** (`src/store.ts`, `useRoomStore`) — room layout/panels; `dataSources` intentionally empty (data is loaded on demand via `useSql`). Panels: `main` (the map view, the only one actually reachable from the UI) and `data` (`placement: 'sidebar'` — registered but currently unreachable since `src/room.tsx` no longer renders `<RoomShell.Sidebar>`). `src/room.tsx` also passes `tileClassName="p-0 bg-transparent"` to `<RoomShell.LayoutComposer>` to kill `@sqlrooms/layout`'s default per-tile `p-2 bg-secondary/10` padding/tint — otherwise the light-theme tint shows as a border around the map.
- **Zustand `useMapStore`** (`src/zustand/useMapStore.ts`) — all playback/UI state: `time`, `timeRange`, `displayTimeRange`, `viewTimeRange`, `isPlaying`, `timeScale`, `selectedModes`, `visibleLayers`, `scenarioType`, `sampleSize`, `networkControl` (see the comment block at the top of the file for what each time range means).
- The rAF playback loop in `MapView.tsx` reads/writes Zustand via `useMapStore.getState()` to dodge closure-stale-value traps. Components subscribe with `useShallow` + atomic selectors to avoid re-renders during playback.

### Layer registry & visibility
- `src/constants/layers.ts` centralizes layer identity: `LAYER_IDS` (`trips`/`road-service`/`road-control`/`heatmap`/`od-arc`/`stop-counts`/`shelter-capacity`), `LAYER_CONFIG` (id + title + `defaultVisible` + `requires`), and `INITIAL_VISIBLE_LAYERS` derived from it. **`LAYER_CONFIG` order is the Layers panel order** (not the draw order): Trips · Heatmap · OD Arc · Shelter Capacity · Road Service · Stop Counts. The static facility markers (Stations bus/metro dots, Shelters dots) were removed from the panel and their code deleted (`useFacilityPointsLayer.ts`, `LAYER_IDS.STATIONS/SHELTERS`, `FACILITY_*_COLOR`, the manifest's `busStopsUrl`/`metroStationsUrl`/`sheltersUrl`): nothing else used them — Stop Counts joins `bus_stops.csv`/`metro_stations.csv` itself via its own query, Shelter Capacity carries its own X/Y.
- `useMapStore.visibleLayers` (`Record<LayerId, boolean>`) + `toggleLayer(id)` hold the on/off state; each layer hook/section in `MapView.tsx` reads its own `visibleLayers[LAYER_IDS.X]` to decide whether to build/return the layer.
- `LayerPanel.tsx` renders the checkbox UI (top-right stack, 284px wide, with `NetworkControlToggle` and `ModeSelector`) driven by `LAYER_CONFIG`/`toggleLayer` — adding a layer to the panel means adding one entry to `LAYER_CONFIG`, no other UI change needed. Titles are `whitespace-nowrap` (the longest, "Shelter Capacity · 避難所飽和率", leaves ~10px of slack at 284px — widen the stack in `MainView.tsx` before adding a longer title). `ModeSelector.tsx` tints the WALK/CAR/BUS/RAIL labels from `AGENT_MODE_TRIP_COLORS`. Entries whose `requires` url is `null` for the current scenario/sample size/control are disabled and dimmed with 「此組合無資料」 rather than hidden (see "Scenario switching" above). Both checkbox lists (Mobility Modes, Layers) use `accent-white` — checked stays white, not the browser-default/cyan accent. `NetworkControlToggle` uses the shadcn `Switch` (`components/ui/switch.tsx`), not a checkbox.
- Trips and the per-agent scatter dots ("Points") are **one** user-facing layer, `LAYER_IDS.TRIPS` ("移動軌跡") — there is no separate Points id/checkbox anymore. They remain zoom-LOD-exclusive internally: `MapView.tsx` only builds the trips `TripsLayer` when `currentZoom <= ZOOM_THRESHOLD` (11, from `usePointsLayer.ts`), and `usePointsLayer` only builds the dots above it; both read `visibleLayers[LAYER_IDS.TRIPS]`. **Don't confuse the LOD dots (`usePointsLayer`, replaces trips when zoomed in) with `LAYER_IDS.STATIONS` (static bus/metro facility markers, unrelated layer, unrelated data source)** — the naming collision bit us once already.
- **Road Service** (`LAYER_IDS.ROAD_SERVICE`, `hooks/useRoadServiceLayer.ts`, visual encoding in `constants/roadService.ts`, legend `components/RoadServiceLegend.tsx`) — reads `06_road_service/road_service_<run>.parquet` (hourly: one row = link × hour, `level` 1–6 from `speed_ratio`, 1 smoothest) through DuckDB (`useSql`, only once the layer is on). Rows are bucketed by `hour_start` in JS (sorted by level ascending so congested links draw on top); the bucket with `hour_start <= time < hour_end` is drawn as a plain `PathLayer` (`positionFormat: 'XY'`, flat lon/lat arrays). Colour/relative width come from README §4 via `ROAD_LEVEL_HEX` (single source — legend swatches use it, `ROAD_LEVEL_COLORS` is derived) and `roadWidthPx`; width is scaled 0.6×–1.6× across the map's zoom range. Data ends at hour 15 (54000 s); after that nothing is drawn. Pushed **first** in `MapView.tsx` so it sits beneath everything. Legend: title "Road Service" + 「道路服務水準（速率比，逐小時）」, a continuous 10px-wide level-1…6 colour bar in a CSS grid with the level number and the speed-ratio range (`ROAD_LEVEL_LABELS`), fixed width `ROAD_SERVICE_LEGEND_WIDTH_PX` = 232px (the Timebar is pushed right by this).
- **Road Control** (`LAYER_IDS.ROAD_CONTROL`, `hooks/useRoadControlLayer.ts`, legend `components/RoadControlLegend.tsx`, default visible) — `07_road_control/road_control.parquet` (~12k links; `measure` = closure / car_ban / bus_lane, colours `ROAD_CONTROL_HEX`). Shown only when Network Control is on (`roadControlUrl` non-null); filtered by `start_s <= time < end_s` (whole-run closures have a negative `start_s`). Drawn right above Road Service.
- The map's own zoom is clamped to `[MAP_MIN_ZOOM, MAP_MAX_ZOOM]` = `[10, 15]` (`constants/map.ts`, passed as `minZoom`/`maxZoom` props to react-map-gl's `<Map>`) — zooming further than 15 doesn't add resolution this dataset can use, and `useStopCountsLayer`'s clustering ceiling is derived from the same constant (see below), so changing `MAP_MAX_ZOOM` is the one place to touch if the zoom range ever needs to change.

### Rendering pipeline (zero-copy)
- `MapView.tsx` — MapLibre basemap + `MapboxOverlay` Deck.gl overlay; runs the `requestAnimationFrame` playback loop; composes layers in order road-service → road-control → heatmap → od-arc → points (LOD dots) → stop-counts → shelter-capacity → trips (later pushes draw on top). Also wires a single `getTooltip` callback into the overlay, branching on `info.layer.id` (`'stop-counts-layer'` / `'shelter-capacity-layer'`) to show a hover tooltip. The top-left box (`left-14`, so it doesn't cover MapLibre's zoom buttons at x≈10–39) shows Time (HH:MM:SS), Zoom and the **`Evac Rate`** line, all default white except the Evac Rate *value*, which is `#DF9651` (≈8.3:1 contrast on the dark basemap, ≈5.2:1 worst case over a light one). The map style comes from `BASEMAP_STYLE` (`constants/basemap.ts`). The left panel is framed like every floating panel (`PANEL_FRAME`). The bottom-left legend stack now lives in `MainView.tsx` (not here — see "Floating panel layout" below). Shelter Capacity's legend rows come from `SHELTER_STATUS_LEGEND` + `SHELTER_STATUS_COLORS` in `constants/map.ts` (same colour table as the layer).
- `src/components/custom_layer/arrowTripsLayer/ArrowTripsLayer.ts` — a `CompositeLayer` that reads Arrow `RecordBatch` buffers directly. It slices the underlying `Float32Array`/`Uint8Array` (`paths`, `timestamps`, `modes` columns) via `subarray` using the batch's `valueOffsets`, rebuilds `startIndices` (offset ÷ 2 for [x,y] pairs), and feeds typed-array `attributes` straight into a per-batch `TripsLayer` — no JSON parsing. `updateState` caches the recomputed indices.
- `hooks/usePointsLayer.ts` — builds a single `ScatterplotLayer` (all agents as GPU instance attributes) as the LOD replacement for trips once zoomed in past `ZOOM_THRESHOLD`. Caches the per-agent flattened path/timestamp/mode arrays in a `useRef` keyed on `arrowTable` identity, then re-fills `positions`/`colors` typed arrays every render by interpolating each agent's position at `time` (binary search over each agent's own timestamp array, not a linear scan) — avoids re-parsing the Arrow table every frame.
- `hooks/useHeatmapLayer.ts` — reads `08_heatmap/heatmap_<run>.parquet` through its own `useSql` (zero-row query while the layer is off): rows with `t + 300 > from AND t < to` are `SUM(count)`-ed per `link_id × mode` and joined to `heatmap_links.parquet` for the polyline. One plain `PathLayer` per selected mode (own colour; mode filtering is done in JS, not by re-querying), additive-blended; count → alpha/width on a log scale normalised to that mode's max in the window. Gated behind the 300ms-debounced `timeRange` (frozen while `isPlaying`) so scrubbing doesn't re-query every frame. Windows of ~15 min return ~50k links.
- `hooks/useODArcLayer.ts` — builds one `ArrowODArcLayer` from its own OD parquet query (see above), filtered by `timeRange`/`selectedModes`.
- `hooks/useStopCountsLayer.ts` — station-level waiting-crowd bubbles with **zoom-adaptive clustering**. Two data quirks drove its design: (1) `bus_stops.csv` encodes one row per *route-stop pairing*, so a single physical stop pole commonly has several `stop_id`s at the identical coordinate (up to 16, in one measured case) — rows are first grouped by raw `stop_id`/mode, then re-grouped by rounded coordinate (`LOCATION_PRECISION` = 6 decimals) so one physical station renders as one bubble with its waiting counts summed, not several overlapping circles; (2) even after that, ~554 physical stations is too many bubbles to show at once at low zoom, so a `supercluster` spatial index (built once per mode, since bus/metro are kept in separate indices so a bubble's color stays meaningful) is queried per zoom level to merge/split bubbles — re-clustering only happens on zoom change, while the per-frame (time-dependent) work is just summing each *currently visible* cluster's live waiting values via the same binary-search step-lookup pattern as `usePointsLayer`. Renders a `ScatterplotLayer` (radius ∝ `sqrt(waiting)`) plus a `TextLayer` printing the exact summed count inside each circle — no additive/glow blending, it made dense areas unreadable.
  - ⚠ **Supercluster `maxZoom` gotcha**: querying `getClusters(bbox, zoom)` at `zoom === options.maxZoom` still returns the *clustered* tier — only `zoom > options.maxZoom` returns fully unclustered raw points (see `supercluster/index.js`'s `_limitZoom`: it builds a dedicated raw tree at `trees[maxZoom + 1]`). So the constructor's `maxZoom` must be set to **one less** than the highest zoom you'll ever query at (`CLUSTER_MAX_ZOOM = MAP_MAX_ZOOM - 1`), while the query-side clamp uses `MAP_MAX_ZOOM` itself. Getting this off-by-one backwards silently caps declustering — bubbles stop shrinking no matter how far you zoom in, and it looks like a broken/ignored zoom level rather than an off-by-one.
- `hooks/useShelterCapacityLayer.ts` — one `ScatterplotLayer`, colored by the `status` field (`SHELTER_STATUS_COLORS`: unused/under_capacity/over_capacity/full = README §4 `#9AA0A6 / #A6D96A / #FDAE61 / #D7191C`; Chinese labels in `SHELTER_STATUS_LABELS`) with radius scaled by `load_ratio`. Same forward-fill step-lookup as stop counts, no clustering (shelters are few enough not to need it).
- `arrowODArcLayer/` is **live** (used by `useODArcLayer`); `arrowPathLayer/` is no longer used by anything (Heatmap moved to a plain `PathLayer`). `arrowODArcLayer/geoFanceLayer/` (geofence-based OD filtering) is still unused/WIP.

### Mode filtering (GPU bitmask)
- Mobility modes (WALK/CAR/BUS/RAIL) map to bits `[1,2,8,16]` (`src/constants/map.ts`, `MOBILITY_MODE_BITS`; bit `4` is a reserved/unused slot, never present in the source data).
- `ModeSelector` toggles bits in `selectedModes`; `MapView` OR-reduces them into a single bitmask passed as `filterBitMask`.
- `ModeObjectPropsExtension` (`.../arrowTripsLayer/utils/extensions.ts`) is a Deck.gl `LayerExtension` that adds the per-vertex `mode_type` attribute and pushes the bitmask + `colorMap` as a shader uniform (`mode-shader-module.ts`), so show/hide happens in the WebGL shader.

- **Evac Rate** (`hooks/useEvacuationRate.ts`, shown in the top-left Time/Zoom/rate box in `MapView.tsx`, hover for the tooltip) — `rate(t) = Σ weight of rows whose last timestamp <= t / Σ weight × 100`. One `useSql` query per run pulls every row's `list_max(timestamps)` and `COALESCE(n_persons, 1)` as weight (sorted by arrival); the hook builds a cumulative-weight array and playback is a binary-search lookup, no per-frame query. Cumulative: ignores the time window and `selectedModes`. Single people-weighted definition for every run (the old `people_weighted` / `leg_count` split and `FileSet.evacuationRate` are gone); it is based on the sampled agents (hover note: 「人數口徑（依各 agent 的 n_persons 加權），基於軌跡抽樣的 agent。」). The on-screen label is exactly **`Evac Rate`** (capital E and R, one space) — fixed by the user; don't reword, re-case or resize it (`LABEL` in the hook). The display shows `…` while the query is loading and `—` only for combos with no data.

### Basemap (`src/constants/basemap.ts`)
- All basemap config is in `basemap.ts`; `MapView.tsx` only reads `BASEMAP_STYLE`. `DEFAULT_BASEMAP` is `'current'` and **stays that until the user picks another** (they asked to compare first).
- Dev-only URL param `?basemap=<name>` (works under `yarn dev` only; production builds ignore it): `current` (MapTiler `dataviz-dark` if `VITE_MAPTILER_API_KEY` is set, else CARTO `dark-matter-gl-style`), `dark` (CARTO `dark-matter-nolabels-gl-style`), `positron` (CARTO `positron-gl-style`), `nlsc` (國土測繪中心 EMAP raster tiles). The three CARTO style URLs were `curl`ed (HTTP 200, JSON) before being written in.
- `nlsc`: WMTS endpoint `https://wmts.nlsc.gov.tw/wmts`, layer `EMAP`, TileMatrixSet `GoogleMapsCompatible`; the tile URL is the `ResourceURL` template read from `GetCapabilities` (`.../wmts/EMAP/{Style}/{TileMatrixSet}/{TileMatrix}/{TileRow}/{TileCol}` → `default`, `GoogleMapsCompatible`, `{z}/{y}/{x}` — note y before x), `image/jpeg`, CORS `*`, tiles exist z10–z18 (`maxzoom: 18`). Attribution 「國土測繪中心」. Desaturated/darkened via raster paint (`raster-saturation -0.8`, `raster-brightness-max 0.45`, `raster-contrast 0.1`) over a `#1e1e24` background layer.
- **Load check (no screenshots — verify via DOM/resource timing/console, not images):** all four options load with no console errors (other than the missing `favicon.ico`). `current`: MapTiler style + tiles HTTP 200, ≤ ~270ms; `dark` / `positron`: CARTO style + vector tiles HTTP 200, ≤ ~150ms; `nlsc`: 31 raster tile requests, all HTTP 200, median ~180ms, max ~290ms. The attribution control shows the right credit for each (the nlsc one reads 「國土測繪中心」). Don't take screenshots to judge basemaps — the user compares them by switching `?basemap=` themselves.
- **Early visual impressions (from a one-off trial before screenshots were dropped; the user makes the final pick)** (pt20, Trips + Heatmap + OD Arc + Road Service all on, 1600×900, zoom 10.6; Heatmap's additive glow can't be told apart from OD/Trips with everything on, so it wasn't judged separately; zoomed-in views weren't checked):
  - `current` (MapTiler dataviz-dark): dark, muted labels. Trips (white/yellow), OD Arc (red/blue) and Road Service (green) are all clear; panel edges separate fine.
  - `dark` (CARTO no-labels): darkest, highest contrast — every layer pops the most. No place names at all, so orientation relies on coastline/rivers.
  - `positron`: **not suitable as is.** Trips are white/pale-yellow and the trips/heatmap layers are additively blended, so on a near-white map they vanish; red OD / blue walk / green roads stay visible. The dark panels separate from it very clearly (but the new 1px `white/15` border is invisible there; the dark fill does the work).
  - `nlsc`: mid-grey after desaturation, with dense zh-TW labels baked into the raster (cadastral/section numbers, contour labels) that can't be hidden and compete with thin road/trip lines; Trips/OD still readable, less contrast than the dark styles. Fine for Taiwan-specific detail, noisy as a default.
  - Recommendation recorded: keep `current`; use `dark` if place names aren't needed; don't use `positron`; `nlsc` only with lower `raster-brightness-max` / if local labels are wanted.

### Floating panel layout (`MainView.tsx`, `constants/layout.ts`)
- Every floating panel (right-hand stack, top-left info box, legends, Timebar card, scenario tabs) uses `PANEL_FRAME` = `rounded-lg border border-white/15 backdrop-blur-md` — a 1px translucent light edge + 12px backdrop blur + one corner radius — so panel edges stay separable from any basemap, dark or light. (Before: right panels/legends had an opaque `slate-700` border + 8px blur, the Timebar a `ring-1` with no border + 12px blur and 14px radius, the left box no border/no blur/4px radius.)
- The bottom-left legend stack and the Timebar share **one** bottom offset, `PANEL_BOTTOM_PX` (= 40: the MapLibre attribution's top edge is 34px from the bottom, plus 6px), so their bottom edges are aligned and the Timebar no longer overlaps the attribution. The Timebar wrapper is positioned with explicit `left`/`right` instead of centring: normally both equal `calc((100% - min(90%, 72rem)) / 2)` (the old centred 90%/max-6xl box); while any legend is visible, `left` becomes `max(that, PANEL_EDGE_PX + legendWidth + LEGEND_TIMELINE_GAP_PX)`, where `legendWidth` is measured by a `ResizeObserver` on the legend stack (0 when every legend is hidden → Timebar returns to its original place). `left` has a 150ms transition. Measured at 1600×900: Road Service legend 232px wide → Timebar left 224 → 268, width 1152 → 1108 (at 1280 wide: left 64 → 268, width 948). ## Conventions
- **`apache-arrow` is pinned to `17.0.0`** (exact, plus `resolutions`/`overrides` in `package.json`). Do NOT bump it. The SQLRooms packages pin `17.0.0` and `@duckdb/duckdb-wasm` requires `^17`; if a second arrow version (e.g. 21) gets hoisted, the SQLRooms connector's `new arrow.Table(batches)` receives RecordBatches built by a *different* arrow instance, the internal `instanceof RecordBatch` check fails, and the Table constructor recurses infinitely → `RangeError: Maximum call stack size exceeded` on every query. Keep one arrow version across the whole tree.
- **Time unit is seconds everywhere** (timestamps are seconds after the alert; the sim runs to ~69h and the latest arrival is ~46h, so `TimeLine.tsx`'s `HARD_MAX_SEC` is 72h, not 24h), in both Zustand and DuckDB queries. Do not mix in JS milliseconds (formatting helpers in `timebar/utils.ts` multiply by 1000 only for display).
- Path alias `@/` → `src/` (configured in `vite.config.ts` and tsconfig).
- shadcn/ui configured via `components.json` (style `radix-nova`, base color neutral); UI primitives in `src/components/ui/`.
- Much of the codebase has Traditional Chinese comments; match the surrounding language when editing existing files.
- Deploy target is Netlify (`netlify.toml`): `npm run build` → `dist`, with `CI=false` and increased Node heap.
- `sim_data/` is git-ignored (large delivered test batch, not part of the repo) — local dev depends on it existing on disk plus a standalone http-server pointed at it (see Commands above). Don't assume it's present in CI/build environments.
